# Host collection routes

Work through every source on a best-effort basis. If a source fails or is blocked, note the reason, try an available fallback, then continue to the next source. Save partial results and continue with available evidence and offer facts through saved research, saved angles and ad preparation.

Use the selected client and the current get_workflow sourceCollectionPlan. Browser connector, built-in browser and web fetch are alternatives according to this host’s capabilities. Local scripts are optional. Follow visible pagination and replies, save partial progress and observed continuations, and distinguish blocked, failed, skipped, no matching items and partial pages.

Save with save_record(clientId, kind: research, title, operationId, payload). Retain operationId across retries. Payload schemaVersion is "1". Each entry uses sourceId to join sources[].id. Metadata fields: platform, provider_item_id, parent_id, author, source_created_at, captured_at, subject, target_name, target_role, target_url, voice_class, buyer_status, offer_match, raw_record. Sources carry status, reason, retrievedAt, itemCount, collector, continuation and coverage.

Use to-vault.mjs to assemble local source files into one complete bundle. Read back all saved payload parts and retain every record id. Raw research is not published synthesis; save_record copy is not native ad-copy publication. Brand memory changes use brand/client tools. Reports and transcript-only observations retain host provenance, not app scraper/method authority.

Structured outputs use payload.collectorOutputs: ad_library_scan (existing ads[] rows), competitor_content (winning_patterns[]), competitor_decode (reports[] and ads[]), audience_research (report text). Keep original app-shaped fields and source relationships. Native adapters pin these inputs without updating client columns. Supplied decode/pattern outputs are transported unchanged; this does not supply a new interpretation method or claim a transcript is a visual teardown.
